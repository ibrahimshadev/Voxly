# Dikt Cloud: Auth, Sync & Public Meeting Share Pages

## Context

Dikt is currently a 100% local desktop app (Tauri v2 + SolidJS): SQLite at `dikt/dikt.db` holds transcription history, meetings, transcripts, summaries; media lives at `dikt/meetings/{id}/recording.mp4` (~500–800 MB/hour). There is no backend and no auth anywhere. The owner wants: (1) login, (2) after login all history & meetings backed up/synced to the cloud (restorable on any machine), (3) every meeting shareable as a public web page showing video + transcript + summary.

**Decisions made by the owner:**
- **Backend: Cloudflare stack** — Workers + D1 + R2 (zero-egress R2 chosen deliberately for video).
- **Scope: desktop app + public share pages only.** No authenticated web dashboard this iteration.
- **Video: auto-upload everything** — every finished recording uploads in the background; text data syncs automatically when logged in.
- **Auth: Google OAuth (system browser) + email OTP** (6-digit code typed in app).
- **Local-first stays:** app fully functional logged out; cloud is additive.

**Stack choices (validated):** Hono on Workers in new `server/` dir; drizzle-orm + drizzle-kit for D1; **better-auth** (pin exact version) with `emailOTP` plugin + Google provider + `bearer` plugin; **Resend** for OTP emails; `aws4fetch` for S3-presigned R2 multipart. Auth rationale: DB-backed revocable sessions (opaque token in keyring, server-side kill switch) beat hand-rolled JWT or openauth for a desktop client; only ~3 custom routes needed for the desktop Google handoff.

**Session model:** better-auth DB sessions, 90-day sliding expiry, no separate refresh token. Token stored via the existing dual keyring + XOR-fallback pattern in `settings.rs` (keyring `("dikt", "cloud-session-token")`).

## Architecture overview

```
Desktop (Rust, reqwest + Bearer token)
  ├── /api/auth/*  better-auth (OTP, session)        ┐
  ├── /desktop/google/{start,handoff,exchange}        │ Cloudflare Worker (Hono)
  ├── /api/sync/{changes,push}   ← D1                 │  server/ in this repo
  ├── /api/meetings/:id/upload/* ← R2 presigned parts │
  ├── /api/shares* (create/revoke/list)               │
Public browser                                        │
  └── /s/:slug (SSR page), /s/:slug/video (ranged R2 stream) ┘
```

- **Google login flow:** Rust binds one-shot `TcpListener` on `127.0.0.1:0` → opens system browser (`open` crate) at `/desktop/google/start?port&nonce` → Worker drives Google OAuth (confidential client, secret never leaves Worker) → `/desktop/google/handoff` mints 90-day session, stores single-use SHA-256-hashed handoff code (60 s TTL) → redirects to `http://127.0.0.1:{port}/callback?code&nonce` → Rust exchanges code at `/desktop/google/exchange` for the bearer token. OTP flow is pure API calls, no browser.
- **Sync:** per-row `updated_at_ms` + `dirty` flag + tombstone table locally; server assigns per-user monotonic `seq` (allocated inside one `d1.batch()` — atomic, race-free); pull-then-push; LWW by `updated_at_ms` (server applies if `incoming >= existing`); client cursor = last seen `seq`. Fresh login → full pull restores everything.
- **Video upload:** R2 S3 multipart with presigned part URLs (bypasses Worker body limits). Fixed **16 MiB parts** (R2 rule: all parts equal size except last; ≥5 MiB; ≤10k parts). Persistent local queue with per-part etag journal → resumes across app restarts. Concurrency 1, exponential backoff.
- **Share page:** unlisted-public, slug = `nanoid(22)` (~130 bits), live reference (renders current transcript/summary), revocable. Video streamed through the Worker from the R2 binding with full Range/206 support → revocation is immediate (no presigned URL leakage, `no-store`). MP4s already have `+faststart`, so seeking works. Owner playback in the app uses a 1 h presigned GET instead.

## D1 schema (domain tables; auth tables generated by `@better-auth/cli`)

All domain tables keyed `(user_id, id)` with `updated_at_ms`, `deleted` tombstone flag, `seq` + index `(user_id, seq)`:

- `user_sync(user_id PK, last_seq)` — per-user change counter
- `meetings(user_id, id, title, started_at_ms, ended_at_ms, duration_secs, has_video, has_mic, has_system_audio, file_size_bytes, status, transcript_status, transcript_error, assemblyai_transcript_id, video_state TEXT DEFAULT 'none' /* none|uploading|uploaded, server-authoritative */, video_size_bytes, updated_at_ms, deleted, seq)`
- `meeting_transcripts(user_id, meeting_id, json, updated_at_ms, deleted, seq)` — **compact** JSON (D1 ~2 MB value limit; reject >1.8 MB with typed error)
- `meeting_summaries(user_id, meeting_id, json, created_at_ms, provider, updated_at_ms, deleted, seq)`
- `history(user_id, id, text, created_at_ms, duration_secs, language, mode_name, original_text, updated_at_ms, deleted, seq)`
- `uploads(user_id, meeting_id, s3_upload_id, r2_key, part_size, total_size, created_at_ms)` — in-flight multipart
- `shares(slug PK, user_id, meeting_id, created_at_ms, revoked_at_ms)` — NULL revoked = active
- `desktop_handoff(code_hash PK, session_token, user_id, expires_at_ms)`

Not synced: `transcript_started_at_ms`; statuses `recording`/`processing` are never pushed (client filter) so other devices can't mis-reconcile live recordings. Meeting tombstone push cascades server-side: tombstone transcript/summary, revoke shares, abort multipart, `waitUntil`-delete R2 object.

## API contract (summary)

`/api/*` requires `Authorization: Bearer <token>` (401 otherwise); no CORS on `/api/*`; `/s/*` public.

| Area | Endpoints |
|---|---|
| Auth (better-auth) | POST `/api/auth/email-otp/send-verification-otp`, POST `/api/auth/sign-in/email-otp` (→ `set-auth-token` header), GET `get-session`, POST `sign-out` |
| Desktop Google | GET `/desktop/google/start?port&nonce` → 302 Google; GET `/desktop/google/handoff` → 302 loopback w/ one-time code; POST `/desktop/google/exchange` `{code}` → `{token, user}` |
| Sync | GET `/api/sync/changes?since={seq}&limit≤500` → `{changes:[{type:meeting\|transcript\|summary\|history, id, seq, deleted, updated_at_ms, data?}], next_since, has_more}`; POST `/api/sync/push` (≤50 items, ≤1 MB) → `{results:[{id,status:applied\|stale}], latest_seq}` |
| Upload | POST `/api/meetings/:id/upload/create` `{size_bytes}` → `{upload_id, key, part_size, part_count, parts:[{n,url}]}` (8 presigned, 1 h); `/upload/sign` (re-sign ≤8 parts); `/upload/complete` `{upload_id, parts:[{n,etag}]}` (sets `video_state='uploaded'`, bumps meeting seq); `/upload/abort`; POST `/api/meetings/:id/video-url` `{download?}` → 1 h presigned GET |
| Shares | POST `/api/shares` `{meeting_id}` → `{slug,url}` (idempotent); DELETE `/api/shares/:slug`; GET `/api/shares?meeting_id` |
| Public | GET `/s/:slug` SSR HTML (`X-Robots-Tag: noindex`, OG tags); GET/HEAD `/s/:slug/video` ranged 206 streaming, 404 when revoked |
| Account | DELETE `/api/account` — wipe D1 rows + R2 prefix + sessions (Phase 6) |

## Desktop (Rust) changes

New `src-tauri/src/cloud/` modules:
- `mod.rs` — `CloudManager` in `AppState` (`state.rs`); `startup()` from `main.rs` after `db::init()`; base URL env override `DIKT_CLOUD_URL`
- `token.rs` — token + profile storage (keyring + encrypted fallback, mirror `settings.rs` pattern)
- `api.rs` — shared reqwest client, typed endpoints, Bearer injection; 401 → clear token, emit `cloud:status`
- `auth.rs` — loopback listener Google flow; OTP send/verify; logout
- `sync.rs` — pull-then-push engine; cursor in `sync_state`; debounced `tokio::sync::Notify` pokes + 5-min tick; applies remote rows via new `apply_remote_*` helpers in `storage.rs`/`db.rs` (under existing `STORAGE_LOCK`, written with `dirty=0`, guarded `WHERE updated_at_ms <= :incoming`); emits existing `meetings-updated`/`transcription-history-updated` events so UI refresh comes free
- `upload.rs` — queue worker: enqueue on `run_finalize` success (`meeting/manager.rs`) + startup/login rescan; stream 16 MiB parts, journal etags per part, re-sign on 403, complete → `video_uploaded=1` locally (not dirty — server bumped seq); progress event throttled 2/s; meeting deletion aborts upload

New crate dep: `open = "5"`. Everything else (reqwest/tokio/keyring/rusqlite) already present.

**Local SQLite migration v2** (`db.rs`, `SCHEMA_VERSION: 2`; refactor to stepwise `run_migrations`): add `updated_at_ms` + `dirty` (DEFAULT 1 — everything syncs on first login) to all 4 tables; `video_uploaded` on meetings; backfill `updated_at_ms` from `created_at_ms`/`ended_at_ms`; new tables `sync_deletes(entity_type, entity_id, deleted_at_ms)`, `sync_state(key, value)`, `upload_queue(meeting_id PK, state, s3_upload_id, r2_key, part_size, total_size, etags_json, attempts, next_retry_at_ms, error, timestamps)`; partial indexes on `dirty=1`.

**Dirty-flag hooks** (chokepoints only): `db::insert_history_item`, `db::upsert_meeting_meta`, `storage::save_transcript`/`save_summary` → set `updated_at_ms=now, dirty=1`. Deletes (`transcription_history::delete_item`/`clear_history`, `storage::delete_meeting`, `save_index` stale-loop) → insert `sync_deletes` tombstone in same transaction.

**New Tauri commands** (in `commands.rs`, registered in `main.rs`): `cloud_login_google`, `cloud_login_otp_send`, `cloud_login_otp_verify`, `cloud_logout`, `cloud_get_account`, `cloud_sync_now`, `cloud_get_upload_status`, `cloud_retry_upload`, `cloud_get_video_url`, `share_create`, `share_revoke`, `share_list`. Events: `cloud:status`, `cloud:upload-progress`.

**Semantics:** logout keeps local data + cursor, clears token, stops workers. Account switch (different `user_id` than `sync_state.last_user_id`): reset cursor, mark all dirty → merge-upload into new account. `MeetingDetail` gains `video_local: bool` (file exists); `MeetingMeta` gains `video_uploaded: bool`.

## Security

Opaque revocable session token over HTTPS only; Google secret confined to Worker; handoff code single-use/60 s/hashed; OTP rate-limited via better-auth **database** rate-limit storage (Workers memory isn't shared) + attempt cap; R2 keys `users/{user_id}/meetings/{meeting_id}/recording.mp4` (prefix wipe for account deletion), bucket never public, presigned URLs 1 h/exact key; every query scoped by session `user_id`; share revocation immediate (`no-store`, Worker-checked per range request).

## Key risks & defaults

- **D1 ~2 MB value limit** vs transcript JSON: push compact JSON (~300–600 KB for 2–3 h — OK); server rejects >1.8 MB typed; contingency = spill to R2 with D1 pointer (deferred).
- **better-auth API drift**: pin version; verify `emailOTP`/`bearer`/`signInSocial` signatures against current docs at implementation time (context7 available).
- **LWW clock skew**: accepted for single-user multi-device; server `>=` tiebreak.
- **Tauri CSP**: none today so remote https video plays; if a CSP is ever added include `media-src`/`connect-src` for the worker host.
- Multi-account: one at a time, switch = merge-upload (documented above). Password-protected/expiring shares = future work.
